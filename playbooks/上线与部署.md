# 上线与部署（内网新机器）

**什么时候用**：要把本项目部署到一台新的内网机器（macOS 或 Linux），或因换机、重装、迁移需要把线上数据搬到另一台机器时。触发语示例：「把服务装到这台机器上」「换台内网服务器跑」「数据搬过去」。
**做完手上有什么**：一份 `logistics-data-<日期>.tar.gz` 数据包 + 目标机上 `launchctl print`（或 PM2 列表）**running** 的证据 + 6 行自检输出（监听端口 / 健康检查 / 局域网匿名口令 / external / 资源版本号 / skipped）+ 一句「密钥可解密」的确认。

## 步骤

1. **在源机做一致性数据包（绝不在服务运行时 `cp` 库文件）**
   - 命令 / 做法：
     ```bash
     cd /path/to/物流数据监控
     mkdir -p .deploy-tmp/data
     node -e "const{DatabaseSync}=require('node:sqlite');const d=new DatabaseSync('data/logistics.sqlite',{readOnly:true});d.exec(\"VACUUM INTO '.deploy-tmp/data/logistics.sqlite'\");d.close();"
     cp data/.settings.key .deploy-tmp/data/.settings.key
     tar -czf /tmp/logistics-data-$(date +%F).tar.gz -C .deploy-tmp data
     shasum -a 256 /tmp/logistics-data-$(date +%F).tar.gz > /tmp/logistics-data.sha256
     ```
   - 判据：`integrity_check` 为 `ok`，并核对关键计数（实测样例：物流单 **198**、轨迹 **488**、用户 **2**、同步间隔 **30** 分钟、加密密钥项 **3**）。两个文件必须在同一个包里，`.settings.key` 权限 `-rw-------`；`data/*.bak-*` 与 `server.log` 不入包。

2. **校验目标机 Node ≥ 22.5.0 与内置 sqlite**
   - 命令 / 做法：
     ```bash
     node -v && node -e "require('node:sqlite');console.log('sqlite-ok')"
     ```
     宝塔/Linux 用绝对路径装：面板 →「软件商店」→「Node.js 版本管理器」→ 装 v22.x，然后
     ```bash
     ls -d /www/server/nodejs/v22*
     /www/server/nodejs/v22.22.3/bin/node -e "require('node:sqlite');console.log('sqlite-ok')"
     ```
   - 判据：版本输出 ≥ `v22.5.0` 且打印 `sqlite-ok`。宝塔的「命令行版本」保持**未设置**（设了会清掉 PM2 的 NVM 设置），所以后续 Node 命令一律用绝对路径。

3. **把代码与数据包搬到目标机并解压到项目根下的 `data/`**
   - 命令 / 做法：
     ```bash
     mkdir -p /path/to/物流数据监控 && cd /path/to/物流数据监控
     shasum -a 256 -c /tmp/logistics-data.sha256
     tar -xzf logistics-code-<日期>.tar.gz -C .     # 首次部署；更新时同样只覆盖代码
     tar -xzf logistics-data-<日期>.tar.gz -C .     # 解出 data/logistics.sqlite 与 data/.settings.key
     ls -l data/ && ls src/server.mjs
     ```
   - 判据：`shasum -c` 输出 `OK`；`data/logistics.sqlite` 与 `data/.settings.key` 同时存在且 `.settings.key` 为 `600`（否则 `chmod 600 data/.settings.key`）；更新场景下**绝不覆盖 `data/`**。

4. **写 `.env` 固定端口、库路径与显式账号**
   - 命令 / 做法：
     ```bash
     cd /path/to/物流数据监控
     cat > .env <<'EOF'
     PORT=3000
     DATABASE_PATH=./data/logistics.sqlite
     SECRET_KEY_PATH=
     APP_USERNAME=opsadmin
     APP_PASSWORD=<换成强口令>
     EOF
     chmod 600 .env
     ```
   - 判据：`SECRET_KEY_PATH` 留空（即用 `./data/.settings.key`，与数据包一致）；`APP_USERNAME` / `APP_PASSWORD` **必须非空**，否则 `/api/health` 会进入演示模式。注意这两个变量只在 `users` 表为空时创建管理员，本次是搬库，账号仍是库里的（迁移后仍是 `demo/demo123`）→ 上线第一件事改口令。

5. **注册自启并确认只有一个实例**
   - 命令 / 做法（macOS，把 plist 里的路径改成本机绝对路径）：
     ```bash
     pkill -f 'src/server.mjs'                       # 先停手动实例，否则 KeepAlive 抢端口无限重启
     sed -e "s#<项目根>#$(pwd)#g" -e "s#<node路径>#$(command -v node)#g" \
       deploy/com.logistics.monitor.plist > ~/Library/LaunchAgents/com.logistics.monitor.plist
     launchctl load -w ~/Library/LaunchAgents/com.logistics.monitor.plist
     launchctl print gui/$(id -u)/com.logistics.monitor | grep -E 'state|pid'
     ```
     Linux/宝塔等价做法：面板 →「网站」→「Node 项目」→ 项目目录 = 项目根、Node 版本选 v22.x、启动选项 `src/server.mjs`、端口 3000、运行用户 `www`、勾选 PM2 守护，然后保存。
   - 判据：`launchctl print` 显示 `state = running` 且有 pid（宝塔列表显示「运行中」）；`pgrep -fl 'src/server.mjs'` 只有一行；`lsof -ti tcp:3000` 只有一个 PID；代码更新后重启统一用 `launchctl kickstart -k gui/$(id -u)/com.logistics.monitor`（宝塔点「重启」）。

6. **上线自检（六项，逐条留输出）**
   - 命令 / 做法：
     ```bash
     curl -s -o /dev/null -w 'health HTTP %{http_code}\n' http://127.0.0.1:3000/api/health
     LAN=$(ipconfig getifaddr en0 || hostname -I | awk '{print $1}')   # macOS 用前者，Linux 用后者
     echo "探测地址 $LAN"
     curl -s http://$LAN:3000/api/health | grep -o '"demoAccount":[^,]*'   # 期望 null
     curl -s http://127.0.0.1:3000/ | grep -o 'app.js?v=[0-9]*'            # 记下版本号，之后可自证
     curl -s -o /dev/null -w 'admin-settings HTTP %{http_code}\n' http://127.0.0.1:3000/api/admin/settings   # 期望 401
     E2E_PORT=3210 npm run test:browser 2>&1 | tail -6
     ```
   - 判据：① 健康检查 `HTTP 200`；② 局域网地址访问 `demoAccount` 为 `null`（拿到口令即失败）；③ 未登录管理接口 401；④ 浏览器 E2E 输出「**外部域名请求…（无）**」且 `通过 N / M` 中 N = M；⑤ 浏览器打开 `http://<内网IP>:3000`，用真实账号**登录成功**并能看到与源机一致的物流单总数；⑥ 打开「接口配置」页，customer / key / appKey 显示**掩码**（如 `DE••••34`）而不是空白或报错 —— 这一条同时证明 `.settings.key` 与数据库成套。

## 常见坑（来自案例集）

| 坑 | 表现 | 规避 |
| --- | --- | --- |
| Node 版本过低（案例 P5） | 启动报 `Cannot find module 'node:sqlite'` | 必须 ≥ 22.5.0；宝塔用绝对路径 `/www/server/nodejs/v22.x/bin/node` 校验 |
| 只搬库不搬密钥（案例 P5） | 「接口配置」页密钥全部空白/解密失败 | `.settings.key` 与 `logistics.sqlite` 一起搬、一起备份；丢失不可恢复 |
| 工作目录不是项目根（案例 P5） | 登录成功但一条数据都没有（静默新建空库） | 自启配置里 `WorkingDirectory`/项目目录 = 项目根；`lsof -p <pid> \| grep data/logistics.sqlite` 确认打开的是同一份库 |
| 演示账号上生产（案例 P1） | 同一网段任何人匿名 `curl /api/health` 拿到可用管理员口令 | `.env` 写死 `APP_USERNAME`/`APP_PASSWORD`；用局域网地址实测取不到口令 |
| 组件资源基路径丢失（案例 P5） | 内网部署后下拉箭头、复选框对勾、弹窗关闭图标全部 404 | `public/index.html` 的 `<script data-shoelace="/vendor/shoelace">` + `public/ui-vendor-path.js` 的 `setBasePath`，并用 E2E 断言外部域名请求为 0 |
| KeepAlive 与手动实例并存（案例 P5） | launchd 报 `Bootstrap failed: 5`，端口反复被抢、无限重启 | 注册自启前先 `pkill -f 'src/server.mjs'` |
| 启动引导同步无异常保护（案例 P2） | 上游一次限流导致进程 exit 1、端口根本不监听 | 换机后先看 `tail -n 40 data/server.log`，必须有启动成功行；无则按 R3 检查引导 try/catch |
| 改代码没重启（案例 P3） | 用户说「刷新了没变化」 | 更新代码后必须重启，并贴出晚于源码 mtime 的启动日志时间戳 |
| 反向代理后回环判断退化（案例 P1） | 经 Nginx 后所有请求都被当成「本机」 | 安全边界落在显式账号 + 管理接口 401 + 3000 端口不对公网放行 |
| SQLite 直接复制（案例 P5） | 快照不一致，恢复后数据缺行 | 取包一律 `VACUUM INTO`，并校验 `PRAGMA integrity_check = ok` |

## 收尾自检

- [ ] `node -v` ≥ 22.5.0，且 `node -e "require('node:sqlite')"` 打印 `sqlite-ok`
- [ ] 数据包 `shasum -c` 为 `OK`，库里 `integrity_check = ok`，关键计数与源机一致
- [ ] `.settings.key` 与库成套、权限 600；「接口配置」页显示掩码而不是空白
- [ ] `.env` 权限 600，`APP_USERNAME`/`APP_PASSWORD` 非空，`SECRET_KEY_PATH` 留空
- [ ] 自启状态 `running`；`pgrep -fl 'src/server.mjs'` 与 `lsof -ti tcp:3000` 各只有一个
- [ ] 健康检查 200；局域网地址访问 `demoAccount` 为 `null`；未登录 `/api/admin/settings` 为 401
- [ ] 浏览器 E2E 外部域名请求为 0，`通过 N / M` 且 N = M
- [ ] 页面上记录下 `app.js?v=` 的版本号，改一次前端资源后该数字必须变化
- [ ] 已用真实账号登录成功并改掉 `demo` 默认口令
- [ ] 3000 端口未对公网放行；备份按日执行且含 `.settings.key`

# 改前端并自证生效

**什么时候用**：改完 CSS / 组件 / 响应式，准备说「已完成」之前；或用户要求「给证据 / 我要看到效果」。
**做完手上有什么**：一份矩阵结果——改前 / 改后各一套截图（多角色 × 多视口）+ 每个采集点的 `getBoundingClientRect()` 与 `getComputedStyle()` 量值，加上一条能复跑的探针或断言。

## 步骤

1. **先定矩阵，再动手写代码**
   - 命令 / 做法：写下三张清单——角色（管理员 / 普通用户）、视口（日常 1920 / 1440 / 1024 / 375；涉及响应式时换成每个断点两侧：`1920,1440,1180,1100,1024,900,760,560,380,375`）、状态（默认 / 侧栏折叠 / 窄屏抽屉 / 多选选中 0、1、6 项 / 弹窗打开）。
   - 判据：矩阵每一格都写出期望值；写不出期望值的格子说明需求没定义清，先问用户再改（案例 C2：只验管理员，普通用户分支塌成 64px 才被发现）。

2. **起一个可复现的临时实例，不拿生产 3000 试**
   - 命令 / 做法（项目根）：
     ```bash
     cp data/logistics.sqlite .probe/probe.sqlite        # 数据类改动用副本；纯样式可用空库
     PORT=3211 DATABASE_PATH=./.probe/probe.sqlite SECRET_KEY_PATH=./data/.settings.key node src/server.mjs
     curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3211/api/health
     ```
   - 判据：health 返回 200。同一份副本库里用**库内真实账号**（`demo/demo123` 只在 users 表为空时生效，案例 P5）；`DATABASE_PATH` / `SECRET_KEY_PATH` 按当前工作目录解析，必须在项目根启动（案例 P5）。

3. **落地下面的探针脚本**
   - 命令 / 做法：把本步代码块存为 `.probe/verify-ui-change.mjs`（只读采集，不写业务数据；`>>>` 用于查进 shadow DOM）。
     **仓库已提供同内容脚本**：[`tools/browser-probes/verify-ui-change.mjs`](../tools/browser-probes/verify-ui-change.mjs)，可直接复制到项目 `.probe/` 使用。
   - 判据：不给账号直接运行时报「缺少探针账号」并以退出码 2 结束，说明脚本可跑、参数生效。

   ```js
   // 前端改动取证：多角色 × 多视口，采几何 + 计算样式并截图；运行方式见下一步的命令。
   import { chromium } from 'playwright';
   const BASE = process.env.PROBE_BASE || 'http://127.0.0.1:3000';
   const PREFIX = process.env.PROBE_PREFIX || 'after';
   const SELECTORS = (process.env.PROBE_SELECTORS || '.app-topbar,.sidebar,.workspace').split(',');
   const VIEWPORTS = (process.env.PROBE_VIEWPORTS || '1920,1440,1024,375').split(',').map(Number);
   const ACCOUNTS = [
     { tag: 'admin', user: process.env.PROBE_ADMIN_USER, pass: process.env.PROBE_ADMIN_PASS },
     { tag: 'member', user: process.env.PROBE_MEMBER_USER, pass: process.env.PROBE_MEMBER_PASS }
   ].filter((account) => account.user && account.pass);
   if (!ACCOUNTS.length) {
     console.error('缺少探针账号：至少给一组 PROBE_ADMIN_USER / PROBE_ADMIN_PASS（要对比角色再加 MEMBER 一组）');
     process.exit(2);
   }
   const browser = await chromium.launch({ channel: 'chrome', headless: true });
   const rows = [];
   for (const account of ACCOUNTS) {
     for (const width of VIEWPORTS) {
       const context = await browser.newContext({ viewport: { width, height: 900 } });
       const page = await context.newPage();
       await page.goto(BASE, { waitUntil: 'domcontentloaded' });
       await page.waitForSelector('#login-form', { timeout: 15000 });
       const fill = (selector, value) => page.locator(selector).evaluate((el, v) => {
         el.value = v;
         el.dispatchEvent(new Event('input', { bubbles: true }));
       }, value);
       await fill('#login-username', account.user);
       await fill('#login-password', account.pass);
       await page.locator('sl-button[type="submit"]').click();
       await page.waitForSelector('.app-frame', { timeout: 20000 });
       // 等条件成立，而不是固定 sleep（案例 T2：过渡动画会让固定等待随机假红）
       await page.waitForFunction((selector) => Boolean(document.querySelector(selector.split('>>>')[0].trim())), SELECTORS[0], { timeout: 10000 });
       const metrics = await page.evaluate((selectors) => selectors.map((raw) => {
         const [host, inner] = raw.split('>>>').map((part) => part.trim());
         const base = document.querySelector(host);
         const el = inner ? base?.shadowRoot?.querySelector(inner) : base;
         if (!el) return { selector: raw, missing: true };
         const rect = el.getBoundingClientRect();
         const style = getComputedStyle(el);
         return {
           selector: raw,
           x: Math.round(rect.x), y: Math.round(rect.y), w: Math.round(rect.width), h: Math.round(rect.height),
           display: style.display, position: style.position, flexWrap: style.flexWrap,
           backdropFilter: style.backdropFilter, fontVariantNumeric: style.fontVariantNumeric,
           heightVar: style.getPropertyValue('--sl-input-height-medium').trim()
         };
       }), SELECTORS);
       const overflow = await page.evaluate(() => document.documentElement.scrollWidth > window.innerWidth + 1);
       await page.screenshot({ path: `.probe/ui-${PREFIX}-${account.tag}-${width}.png` });
       rows.push({ account: account.tag, width, overflow, metrics });
       await context.close();
     }
   }
   await browser.close();
   console.log(JSON.stringify(rows, null, 1));
   const overflowRows = rows.filter((row) => row.overflow);
   if (overflowRows.length) { console.error(`横向溢出：${overflowRows.map((row) => `${row.account}@${row.width}`).join(' ')}`); process.exit(1); }
   ```

4. **采改前基线**
   - 命令 / 做法：
     ```bash
     PROBE_BASE=http://127.0.0.1:3211 PROBE_PREFIX=before \
     PROBE_ADMIN_USER=<管理员账号> PROBE_ADMIN_PASS=<口令> \
     PROBE_MEMBER_USER=<普通用户账号> PROBE_MEMBER_PASS=<口令> \
     PROBE_SELECTORS='.app-topbar,.sidebar,.workspace,sl-select[multiple] >>> .select__tags' \
     node .probe/verify-ui-change.mjs > .probe/ui-before.json
     ```
   - 判据：记录数 = 角色数 × 视口数（默认 2 × 4 = 8 条），截图张数与记录数一致；`grep -c '"missing": true' .probe/ui-before.json` 为 0（不为 0 就是选择器写错，先修选择器再改代码）。

5. **改代码，再确认服务端真的发出新前端**
   - 命令 / 做法：`public/` 下改动无需重启；`src/` 改动必须重启。随后核对版本号：
     ```bash
     curl -s http://127.0.0.1:3211/ | grep -oE '(app|styles|sidebar)\.(js|css)\?v=[0-9]+'
     node -e "const f=require('fs');const m=['app.js','styles.css','sidebar.css'].map(n=>f.statSync('public/'+n).mtimeMs);console.log('文件版本号 '+Math.round(Math.max(...m)))"
     ```
   - 判据：两处版本号相等；两次 curl 版本号不同（`Date.now()` 兜底）或读到的不是这一份 `public/`，都先按 `playbooks/排查改了没生效.md` 第 3、4 步处理，别急着怀疑 CSS（案例 P3）。

6. **采改后证据并逐项比对**
   - 命令 / 做法：
     ```bash
     PROBE_BASE=http://127.0.0.1:3211 PROBE_PREFIX=after <第 4 步的账号变量与 PROBE_VIEWPORTS> \
     PROBE_SELECTORS='<同第 4 步>' node .probe/verify-ui-change.mjs > .probe/ui-after.json
     diff -u .probe/ui-before.json .probe/ui-after.json
     ```
   - 判据：diff 主要出现本次目标项；未改动项若出现，差值必须 ≤ 1px（超过 1px 说明改到了不该动的地方）；`missing` 未增加；脚本退出码 0（报「横向溢出」直接算失败）。

7. **读计算样式与几何，而不是只看截图**
   - 命令 / 做法：
     ```bash
     node --input-type=module -e "import fs from 'node:fs';const r=JSON.parse(fs.readFileSync('.probe/ui-after.json','utf8'));console.table(r.flatMap(x=>x.metrics.map(m=>({角色:x.account,视口:x.width,选择器:m.selector,宽:m.w,高:m.h,position:m.position,flexWrap:m.flexWrap,missing:m.missing??false}))))"
     ```
   - 判据：同档位控件高度只有一个值（账户 40 / 筛选 40 / 表格按钮 30，导航 36–48 区间）；不出现 79px、54px、145px 这三个历史数值（案例 C3、C6）；`position` / `flexWrap` / `backdropFilter` 与本次改动目标一致。

8. **人工看改前改后截图**
   - 命令 / 做法：逐张对比 `.probe/ui-before-*.png` 与 `.probe/ui-after-*.png`，优先看最小视口（375）与断点附近的视口（窄屏最容易暴露溢出与折行）。
   - 判据：目标变化肉眼可见，且未引入新的换行 / 溢出 / 遮挡；截图能直接贴给用户，而不是只写「已对齐」。

9. **固化成可复跑资产**
   - 命令 / 做法：把本次契约写进 `tools/browser-e2e.mjs` 的 `check(...)`（等高 + 合理区间的写法），探针脚本留在 `.probe/` 供回归。
     ```bash
     npm run test:browser          # 端口冲突时：E2E_PORT=3212 npm run test:browser
     ```
   - 判据：用例总数不减（基线 108），失败输出能直接指出角色与视口；没有断言的修复视为没完成。

## 常见坑（来自案例集）

| 坑 | 表现 | 规避 |
| --- | --- | --- |
| 只验一个角色（案例 C2） | 管理员正常，普通用户顶栏塌成 64px | 角色维度是矩阵第一维，默认就要两组账号 |
| 断言钉死像素（案例 T2） | 设计把 43px 调成 42px，用例立刻假红 | 断言「等高 + 合理区间」，容差 1px |
| 固定 sleep 抢跑（案例 T2） | 宽度有 200ms 过渡，截图与断言都是中间态 | 用 `waitForFunction` 等条件成立 |
| E2E 共用临时库（案例 T2） | 两个端口并发跑 → `attempt to write a readonly database` 假失败 | 临时库按端口隔离（`data/.e2e-<端口>.sqlite`） |
| 拿生产库试手（案例 P5） | 改坏数据、口令被清 | 先 `cp` 副本库，用 3211 等临时端口 |
| 只截一张图就说「已改好」（案例 T3） | 用户复现时仍是旧样子，反复返工 | 截图 + 量值一起给，标明角色 / 视口 / 状态 |

## 收尾自检
- [ ] 矩阵（角色 × 视口 × 状态）每一格都有期望值与实测值
- [ ] 服务端版本号与文件 mtime 一致，`src/` 改动已重启并留时间戳
- [ ] 改前改后截图成对存在，命名含角色与视口（`.probe/ui-<before|after>-<角色>-<视口>.png`）
- [ ] 量值里有 `getBoundingClientRect()` 与 `getComputedStyle()` 两类，不只截图
- [ ] `missing` 为 0，未改动的选择器差值 ≤ 1px，脚本退出码 0
- [ ] 新增了一条可复跑断言，`npm run test:browser` 全绿且总数不减（基线 108）

# 前端与组件规则

> 来源：工程案例集 C1–C9（另引用 T3 的取证纪律）；每条都对应一次真实事故，实测数字留在条目里。
> 用法：可直接追加到项目 AGENTS.md，或作为提交前自查清单。
> 适用栈：原生 JS + Web Components（Shoelace）+ 无构建 CSS + 常驻 Node 服务。

## 一、必须

### R1 框架尺寸只留一个出处，改动先删失效块
- **规则**：框架级尺寸（侧栏宽、内容区左外边距、断点宽）必须只来自 `public/sidebar.css` 的 `--sidebar-w` / `--sidebar-w-collapsed`；禁止在其它文件或用 px 字面量再写一套；修正框架样式时删除被覆盖的旧块，禁止「在后面再叠一段来覆盖」。
- **为什么**：同一断点下曾叠 4 段框架规则（共 408 行），后写块完整覆盖前块，但前块遗留属性继续生效，侧栏宽度同时存在 232px、硬编码 220px、1180px 断点的 204px 三套（案例 C1）。
- **怎么检查**：
  ```bash
  grep -rn -- "--sidebar-w" public/                      # 只应命中 sidebar.css 的变量定义与引用
  grep -nE "(width|margin(-left)?): *[0-9]+px" public/sidebar.css   # 新增框架级宽高不得用 px（图标/徽标尺寸除外）
  ```
  浏览器判据：1440px 视口下 `.sidebar` 的 `getBoundingClientRect().width = 232`（折叠态 72），`.workspace` 的 `x` 等于该宽度。
- **违反后果**：普通用户顶栏塌成 64px 白块压在品牌上，三套宽度并存导致改哪一处都不确定（案例 C1）。

### R2 fixed 浮层的祖先不得有 backdrop-filter / transform / filter / contain
- **规则**：任何 `position: fixed` 元素（`inset` 按视口基准）的祖先链上，禁止出现非 `none` 的 `backdrop-filter`、`transform`、`filter`、`contain`、`will-change: transform`；确需保留毛玻璃时，在最终生效的块显式写 `backdrop-filter: none` 并附根因注释。
- **为什么**：一段已被完全覆盖的历史规则残留 `backdrop-filter: blur(14px)`，使祖先成为 fixed 后代的包含块，`.user-area`（`inset: 0 0 auto 220px`）宽度变成侧栏内宽 64px（案例 C2）。
- **怎么检查**：
  ```bash
  grep -rnE "backdrop-filter|will-change|contain:" public/*.css        # 逐个确认它是否在某个 fixed 元素的祖先上
  # 前置：先起临时实例（该脚本固定访问 3211）
  PORT=3211 DATABASE_PATH=./.probe/probe.sqlite SECRET_KEY_PATH=./.probe/probe.key node src/server.mjs
  PROBE_USER=demo PROBE_PASS=demo123 node ai-workflow-kit/tools/browser-probes/check-containing-block.mjs
  ```
  判据：输出里 `.topbar` 的 `backdropFilter` 为 `none`，且 `.user-area` 的 `width` 与 `.workspace` 同宽（1440px 视口下约 1208px），不出现 64px。
- **违反后果**：普通用户顶部账号栏宽度塌缩为 64px（只剩左右 padding）并向左溢出，管理员布局却正常（案例 C2）。

### R3 组件高度只改组件高度变量，内容按插槽语义分派
- **规则**：Web Component 的高度必须通过 `--sl-input-height-<size>` 一类组件变量设定；禁止用 `height:` 代替，禁止在 `::part(base)` 上加 padding 参与高度计算；头像 / 文字 / 箭头必须按 prefix、label、suffix 插槽分派，禁止全投默认插槽。
- **为什么**：默认插槽不是 flex 容器 → 内容纵向堆叠被撑到 79px；只写 `height: 48px` 而内部行高仍按 38px 算；`::part(base)` 的 `padding: 8px 14px` 与按变量算出的 line-height 叠加成 54px（案例 C3）。
- **怎么检查**：
  ```bash
  grep -rn -- "--sl-input-height-(small|medium|large)" public/*.css public/app.js
  grep -rn "part(base)" public/*.css                               # 命中处不得含 padding
  ```
  浏览器判据：同一档位控件的 `getBoundingClientRect().height` 只有一个值——筛选区 40 / 表格内按钮 30 / 导航 36–48 / 账户 40（由 `npm run test:browser` 的「等高」断言守住）。
- **违反后果**：侧栏账号按钮 79px、导航按钮 54px、窄屏顶栏被撑到 134px（占手机屏 1/6）（案例 C3）。

### R4 禁止 await 组件动画 Promise
- **规则**：浮层一律 `void dialog.show()` / `void drawer.show()`；需要初始焦点时用 `sl-initial-focus` 事件 + `updateComplete` 兜底接管，禁止 `await` 入场/退场动画。
- **为什么**：`show()` 要等 Web Animations 入场动画结束才 resolve，无合成帧环境（无头浏览器、后台标签页）动画永不结束 → Promise 永远 pending，挂在 `requestAnimationFrame` 上的初始聚焦同样不执行（案例 C4）。
- **怎么检查**：
  ```bash
  grep -rnE "await +[a-zA-Z0-9_.]*\.(show|hide)\(\)" public/app.js
  grep -n "sl-initial-focus\|updateComplete" public/app.js
  ```
  判据：第一条命令的命中行必须全部处于注释中（当前仓库仅 1 处讲解注释）；出现任何执行语句即违反。
- **违反后果**：抽屉停在「正在加载」，数据请求压根没发出（案例 C4）。

### R5 自定义元素一律走 uiKit 适配层，浮层监听器判 target
- **规则**：取值、禁用、监听、聚焦、回车提交必须走 `uiKit`（`fieldValue` / `setDisabled` / `onValueChange` / `focusWhenReady` / `enterSubmits`）；浮层收尾监听器（`sl-after-hide`、`sl-request-close`）首行必须 `if (event.target !== 自身) return`。
- **为什么**：自定义元素不参与 `form.elements`（length 0）、`el.disabled = true` 无效、刚插入文档 `.focus()` 取到 null；`sl-after-hide` 会冒泡，弹窗内下拉收起被误判为「弹窗已关闭」（案例 C5）。
- **怎么检查**：
  ```bash
  grep -n "const uiKit" public/app.js
  grep -rn "form.elements\|\.disabled = true" public/app.js      # 命中只允许出现在注释里
  grep -n -A2 "addEventListener('sl-after-hide'" public/app.js   # 每个监听器紧跟 target 判定
  ```
  判据：`event.target !== ...` 判定数 = `sl-after-hide` 监听器数（当前仓库实测 2 处：drawer 2135 行、dialog 2512 行）。
- **违反后果**：`form.elements.xxx` 取不到值（length 0）；新建账号一选角色弹窗就消失（案例 C5）。

### R6 高度会随内容变化的控件必须锁高
- **规则**：多选 / 标签类控件必须设 `max-options-visible="1"`，并按 size 三档锁 `max-height`（`::part(combobox)`），`::part(tags)` 强制 `flex-wrap: nowrap`；禁止只靠外层 grid 的 `align-items: end` 维持对齐。
- **为什么**：`.select__tags` 是 `flex-wrap: wrap`，组件宽 135px 而单个标签 87px → 一行只放 1 个；组件默认 `max-options-visible` 为 3，选中项一多就换行；外层 `align-items: end` 让同行任一控件变高就顶起整行。实测选中 6 项时控件 40px → 145px、筛选表单 94px → 199px（案例 C6）。
- **怎么检查**：
  ```bash
  grep -rn "max-options-visible" public/app.js
  grep -n "part(combobox)\|part(tags)" public/styles.css
  ```
  浏览器判据：7 个视口 × 选中 0/1/2/3/6 项时控件高度恒为 40px（`sl-select[size="medium"]::part(combobox) { max-height: var(--control-md) }`），标签零裁切。
- **违反后果**：全选 6 项时控件 40px → 145px、筛选表单 94px → 199px，整行对齐被顶掉（案例 C6）。

### R7 字体栈只用本机真实字体，字号字重全量 token 化
- **规则**：`--font-sans` / `--font-mono` 只写本机真实存在的字体，等宽栈必须显式带中文回退；`font-size` / `font-weight` 只允许引用 `--fs-*` / `--fw-*` token；数字列（编码、时间、指标值）必须 `font-variant-numeric: tabular-nums`。
- **为什么**：字体栈首选从未加载的 `Inter` → 装了它的机器与没装的机器两套字形；`--font-mono` 无中文回退，Windows 上中文落到宋体；全站 22 种字号取值，`font-weight` 出现 650（×27）/750/800/900 等非标准字重被就近取整或合成加粗（案例 C7）。
- **怎么检查**：
  ```bash
  grep -rnE "font-size: *[0-9]" public/*.css          # 只允许 token 定义处与已登记例外
  grep -rnE "font-weight: *(650|750|800|900)" public/*.css   # 期望 0 命中
  grep -c "font-variant-numeric: tabular-nums" public/styles.css
  ```
  判据：字号只剩 8 档（`--fs-2xs: 11px` … `--fs-2xl: 28px`）、字重只剩 4 档（400/500/600/700）；当前实测仅 `.data-table .sort-mark` 一处 10px 属已登记例外。
- **违反后果**：同一界面在不同机器字形与粗细不一致；数字列宽随内容跳动（案例 C7）。

### R8 尺寸唯一出处，且承载容器要能被压窄
- **规则**：表格列宽只来自列定义（`colgroup`），`min-width` 只作下限、不得顶开列宽；输入控件宽只由 `--input-width` 决定，网格统一写 `repeat(auto-fill, minmax(min(100%, var(--input-width)), var(--input-width)))`，字段容器必须 `min-width: 0`；主值超长用 `line-clamp` 限行 + `title` 放完整值。
- **为什么**：`td` 上的 `min-width` 会顶开 `colgroup`、`width: 100%` 让宽度由容器决定、`table { width: 100% }` 时浏览器忽略 `max-width` 铺满。实测 1440px 下首页表格目标列宽合计 1177px > 可用 1154px 已横滚；1920px 下「操作」列被撑到 525px 而只放一个按钮；输入框宽出现 132–1080px 十几种取值；固定 320px 的控件放进 `minmax(0, 320px)` 的列会溢出所在列 36px（案例 C8）。
- **怎么检查**：
  ```bash
  grep -n "colgroup" public/app.js
  grep -rn "auto-fill" public/*.css
  grep -c "min-width: 0" public/styles.css             # 字段容器逐个核对
  node .probe/probe-table-metrics.mjs 1280 1440 1920   # 自带临时实例与演示库
  ```
  判据：探针输出「横向滚动：否」，且各列主值折行情况为 1 行。
- **违反后果**：1440px 表格横滚、1920px 操作列 525px 浪费、固定宽控件溢出所在列 36px（案例 C8）。

### R9 局部刷新只重绘该重绘的，并让过期响应失效
- **规则**：筛选 / 翻页只重绘统计卡与表格卡片，禁止重建筛选面板；每次列表请求取递增序号，响应回来时序号不是最新就丢弃；随局部刷新变化的区块（新鲜度、同步进度）必须给固定 id。
- **为什么**：整页重绘导致输入框失焦、滚动跳动；无竞态处理时先发的慢响应会覆盖后发结果；没有可替换锚点的区块在局部刷新后没人更新（案例 C9）。
- **怎么检查**：
  ```bash
  grep -n "shipmentRequestSeq" public/app.js            # 序号定义 + 两处守卫
  grep -n "layoutCleanup" public/app.js                 # 定时器与监听器必须挂进回收列表
  grep -n "sync-freshness" public/app.js                # 局部刷新区块的固定锚点
  ```
  判据：`grep -nE "if \(seq !== .*Seq\) return" public/app.js` 命中（当前 2 处：1451、1457 行）；探针里快速连点两次筛选后，列表条数与最后一次筛选一致，且输入框焦点未丢。
- **违反后果**：输入框失焦、滚动跳动；新鲜度与同步进度区域不再刷新（案例 C9）。

### R10 布局类改动必须留下改前改后的几何与计算样式量值
- **规则**：凡涉及布局、高度、对齐、响应式的改动，必须先用真实浏览器读 `getBoundingClientRect()` 与 `getComputedStyle()` 并留下**改动前**数值，交付时给出同选择器、同视口的改后数值；批量替换 CSS 必须带选择器前缀或负向断言（如 `(?<![-\w])font-size:`），禁止按「推测的位置」直接修。通用测试纪律见 `rules/测试与验收规则.md`，本条只保留前端可判定的部分。
- **为什么**：必填星号换行按推测位置精准修了两轮都没修好，第三轮改成不依赖位置假设的 `flex-wrap: nowrap` 才生效；`.detail-title` 只有 `align-items: center` 而没有 `display: flex`，对块级元素完全无效；674px 单列 grid 里两个小元素分两行（案例 T3）。
- **怎么检查**：按 `playbooks/改前端并自证生效.md` 第 3 步落地探针脚本，用 `PROBE_PREFIX=before` / `after` 各跑一遍并 `diff -u` 两份 JSON；截图与 JSON 都必须进交付物。批量替换后 `grep -c` 复核命中数与预期一致。
- **违反后果**：一轮修错位置，连续两轮白跑；远程协作时只能靠索取截图才发现（案例 T3）。

# 项目交付纪律（可整段追加到项目 AGENTS.md）

> 来源：194 个会话 / 1369 条真实用户发言的复盘。这 6 条分别对应复盘中最高频的摩擦：
> 服务中断与反复启动 73 条、同类问题要全量扫 47 条、口径不一致 13 条、要求自证 27 条、
> "改了没生效"24 条、危险数据操作（清库/重拉）多次。
>
> 写法要求：**可观察、可核销**。"注意重启"没有约束力，"必须贴出启动日志时间戳"才有。

---

## 1. 改了服务端，就必须让运行中的实例生效

- 改 `src/**`、配置、迁移脚本后，**重启正在运行的实例**，并在回复里贴出启动日志的时间戳。
- 没有新时间戳 = 这次改动对用户等于没发生。
- 前端资源改动要确认浏览器拿到的是新资源（资源地址带版本号，或明确告知需要强刷）。

## 2. 修复类需求必须全量扫同类

- 交付时附「同类位置清单」：`文件 + 位置 + 处理结果`（已改 / 不需要改 / 待定）。
- 不允许只改用户指出的那一处就宣告完成——用户会问「其他地方还有没有」，这一问本身就是返工。
- 典型同类：同名 CSS 规则、多个页面共用组件、多个入口调用同一接口、多个角色的同一页面。

## 3. 一个业务概念只允许一个定义

- 同一概念出现在**统计 / 筛选 / 导出 / 详情**多处时，必须互相校验，并补一条断言
  （例：「卡片数字 = 点击后列表的 total」）。
- 发现两处口径不一致时，**先统一口径再改代码**，并说明以哪一处为准、另一处如何折算。
- 真实案例：卡片「未签收」15 票 vs 列表筛选 173 票（占位单被算进未签收）。

## 4. UI / 交互改动必须附可测量证据

- 交付附：**改前改后截图**（关键区域）+ **关键量值**（宽度 / 位置 / 行高 / 对比度）。
  写"已对齐"不算证据，写"宽 232px、垂直居中、对比度 7.56:1"才算。
- 至少覆盖这些分支：**所有角色 / 权限**、桌面与窄屏、空数据与满数据、整页渲染与局部刷新路径。
- 真实案例：只在管理员账号验证侧栏，普通用户走另一套框架，改动对他完全没生效。

## 5. 验收清单是交付物的一部分

- 每条需求一行：**在哪验 / 怎么验 / 期望看到什么**；交付时逐条核销，没做到的明说。
- 不允许用"已优化完毕"覆盖没做完的部分。
- 这一条直接消掉复盘里 13% 的纯确认消息与 9% 的验证追问。

## 6. 危险数据操作一律先走副本

- 清库、重拉、迁移、批量覆盖之前：**副本库 + 临时端口**先演练一遍，确认影响面后再对生产执行。
- 禁止拿生产库试错（真实事故：在生产库反复试密码导致账号被锁 15 分钟）。
- 演练命令形态：

  ```bash
  cp data/app.sqlite .probe/test.sqlite
  DATABASE_PATH=./.probe/test.sqlite PORT=3211 node src/server.mjs &
  PROBE_BASE=http://127.0.0.1:3211 node <探针脚本>
  ```

## 使用建议

- 放进项目 `AGENTS.md` 的**末尾**，标题保持"交付纪律"，便于 Agent 检索。
- 6 条全上也可以，但若项目很小，优先 1、2、4、5 四条（性价比最高）。
- 每条都保留"真实案例"一行：约束力来自具体事故，而不是抽象要求。
